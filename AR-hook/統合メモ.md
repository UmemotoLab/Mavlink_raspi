## 4. 統合時に確認した整合性

1. **原点・高度基準（f6152）とクランプ上限（7f03b）**
   - クランプは `target` / `gps_now` と同じ REF 原点基準の NED（x=北, y=東, z=下）で計算します。
   - 送信時の home 相対高度への変換は `send_local_target()` → `local_down_to_home_relative_alt()` の 1 経路だけです。
   - キーボード `z` の下限は「離陸地点から 0.05 m」（f6152 の意味）を維持し、`t` キーも `alt_above_home_to_local_down()` を使います。7f03b の `commit_target_command()` 集約と両立しています。
2. **`send_setpoint` の yaw 引数化（9c2a5）と送信ロック（95501 / 通信部移行）**
   - `send_setpoint(comm, lat_i, lon_i, alt, yaw_deg=None)` は yaw を `math.radians()` で事前計算し、`comm.setpoint(..., yaw_rad=..., type_mask=MASK)` を呼びます。yaw の設定値は `TARGET_YAW_SEND_DEG`（環境変数で変更可）です。
   - **送信ロックは `MavlinkComm._send_lock` の 1 本だけ**です。`AR-hook1.py` には `mav_send_lock` を置かず、`m.mav.*_send` も直接呼びません（送信ロックが二重にならない構成）。
   - 62a00 の統合時は「`mav_send_lock` を本体側に残し、通信部の `_send_lock` と 2 段にする」版でしたが、**ブランチ側（`ca40f48`）の設計＝通信部 1 本を正**とします。
3. **ATTITUDE 40Hz（12794）と通信部の `set_message_interval`（e22e3）**
   - `set_msg_rate(comm)` は `24`/`33` を 200,000µs、`30` を 25,000µs で **各 1 回だけ**要求します。同じ ID に異なる周期を送る二重要求はありません。
4. **ロック取得順序**
   - 全コードで `io_lock` → 通信部 `_send_lock` の一方向のみです。`io_lock` 保持中の送信呼び出し、`_send_lock` 保持中の `io_lock` 取得は 0 件（AST 検査）。

## 6. 実機に載せる際の注意

1. **未 push のまま使う**: `feature/arhook-fixes` を checkout して実機に載せます。`git push` / `git push --force` / `git tag` は行わず、`main` は `1c6aca1` のまま動かしません。投入前に `git symbolic-ref HEAD` と `git status --porcelain` で、想定どおりのブランチ・クリーンな状態であることを確認してください。
2. **通信はすべて通信部経由**: 送信は `MavlinkComm` の `setpoint` / `takeoff` / `command_long` / `set_message_interval`、受信は通信部の受信スレッド 1 本（`mavlink-rx`）だけです。`AR-hook1.py` から `m.mav.*_send` / `mavutil` を直接呼ばず、`AR-hook1.py` に送信ロックを置きません。
3. **`REF_ALT` の高度スケール**: `GLOBAL_POSITION_INT.alt`（AMSL）と同じスケールで設定してください。Motive の GPS 出力（基準点高度 0）を Pixhawk に入れる構成では `0.0` のままで整合します。
4. **起動時のログ確認**:
   - `✓ 目標Yawを ...° に固定（設定ソース: ...）` と `MASK: 0x....`（9c2a5）
   - `✓ 離陸地点のREF座標: ...` / `✓ 離陸高度到達: home相対 0.50m (target Down=...)`（f6152）
   - `✓ MAVLink接続完了` のあと受信スレッドが 1 本だけ動くこと（e22e3）
5. **ATTITUDE 40Hz の帯域**: 25,000µs（`ATTITUDE_MSG_INTERVAL_US`）が通らない環境では 20,000µs（50Hz）へ変更してください。GPS 系（200,000µs）は据え置きです。
6. **yaw を変える場合**: `AR_HOOK_TARGET_YAW_DEG=180.0` のように環境変数で指定します（0〜360、範囲外は起動時に停止）。`MASK` を変える場合は `AR_HOOK_MASK=0x0DF8`。
7. **クランプ上限**: 既定は水平 1.20 m / 上昇 0.30 m / 下降 0.20 m / 最大速度 0.50 m/s です。実機の `LOIT_SPEED_MS` や運用に合わせて `TARGET_MAX_*` を見直してください。CSV の `Target_*` 列で作動状況を確認できます。
8. **CSV は列の追加のみ**: 既存カラムは削除・改名していません。末尾に `Attitude_Age_ms` / `Attitude_Stale`、続いて `Target_Desired_X_m` 〜 `Target_Update_Source` の 12 列、合計 14 列を追加しています。既存の解析スクリプトは列名参照なら影響を受けませんが、列位置で読む場合は末尾追加分に注意してください（列の一覧は [ファイル概要.md](./ファイル概要.md) の「目標更新のクランプ・レート制限」も参照）。
9. **手動確認項目（実機）**: Guided + Arm → **3 秒後に自動離陸**（`time.time() - start_time > 3` で `send_takeoff_command()`）、キー `u/m/h/l/w/z/t` の移動、検出ロスト時の保持 → 減衰復帰、ATTITUDE 途絶時の目標更新停止（`⚠ MAVLink ATTITUDE が古いため...`）、ケーブル抜けでリンク切断メッセージ + CSV 保存。
