## Pixhawkから受信

| MAVLinkデータ | 値 | 単位・形式 |
|---|---|---|
| `ATTITUDE` | roll・pitch・yaw | ラジアン |
| `GLOBAL_POSITION_INT` | 緯度・経度 | 度を`10⁷`倍した整数 |
|  | 相対高度 | mm（コード内で1000で割りmに変換） |
| `HEARTBEAT` | モード・アーム状態 | 数値フラグ |

受信は `mavlink_comm.py` の受信スレッド1本が行い、最新値を `MavlinkState` として公開します。
`AR-hook1.py` は `comm.snapshot()` を読むだけで、`recv_match()` を直接呼びません。

## Pixhawkへ送信

| MAVLinkデータ | 値 | 単位・形式 |
|---|---|---|
| `SET_POSITION_TARGET_GLOBAL_INT` | 緯度・経度 | 度を`10⁷`倍した整数 |
|  | 相対高度 | m（EKF home＝離陸地点からの高さ） |
|  | yaw | ラジアン（固定ヨー: `TARGET_YAW_DEG`、既定 `0`＝北向き。`AR_HOOK_TARGET_YAW_DEG` で変更可） |
| `MAV_CMD_NAV_TAKEOFF` | 離陸高度 | m |
| `MAV_CMD_SET_MESSAGE_INTERVAL` | メッセージID・周期 | µs |

送信はすべて `MavlinkComm` の薄いAPI（`setpoint` / `takeoff` / `command_long` / `set_message_interval`）を経由し、
内部の送信ロックで直列化されます（前提タスクの `mav_send_lock` を通信部へ移設）。

## ATTITUDE の鮮度管理（姿勢の古さ対策）

- 受信時刻の記録は `monitor_vehicle()` の [1329〜1336行](./AR-hook1.py#L1329-L1336)。`time.monotonic()` で最終受信時刻を保存し、`AttitudeFreshness` が経過時間を公開します。
- 判定は [1931〜1948行](./AR-hook1.py#L1931-L1948)。姿勢計算に MAVLink `ATTITUDE` を使う経路でのみ判定し、古い場合は [2037〜2045行](./AR-hook1.py#L2037-L2045) で自動誘導目標の更新と setpoint 送信を止め、`target` は前回値を保持します（ArduPilot は最後の目標を保持）。

- CSV へ `Attitude_Age_ms`（最終受信からの経過時間[ms]、未受信は nan）と `Attitude_Stale`（古い/未受信なら 1）を末尾に追加しました。既存列は変更していません（ヘッダー [2645〜2646行](./AR-hook1.py#L2645-L2646)、値 [2538〜2539行](./AR-hook1.py#L2538-L2539)）。

## ARhook1のPixhawkへの送受信工程*

1. MAVLink接続 — `connect_mavlink()` が `MavlinkComm` を生成し、`comm.connect()` で接続と `HEARTBEAT` 待ちを行います。実際にシリアルを開くのは [mavlink_comm.py](./mavlink_comm.py) だけで、接続は 1 回だけです。

2. 受信頻度の要求 — `set_msg_rate(comm)` が通信部の `set_message_interval()` を呼びます。`GPS_RAW_INT`（24）と `GLOBAL_POSITION_INT`（33）は 200,000µs（5Hz）を据え置き、`ATTITUDE`（30）は 25,000µs（40Hz）を要求します。40Hz は 12794 の要求値を正とし、周期要求の発行箇所はこの 1 箇所だけです（通信部側は周期を決めない薄い API なので二重発行になりません）。目標を 40Hz で生成するため、5Hz では姿勢が最大 200ms 古くなり Motive 経路と精度差が出るためです（`ATTITUDE` は 40 バイト程度/フレームで、40Hz でも約 1.6kB/s＝1Mbps リンクの 1.5% 前後）。帯域が厳しい場合は 20,000µs（50Hz）が代替値です。GPS は 5Hz 更新のため周期を上げても情報が増えません（`GPS_RAW_INT` は位置計測には使用していません）。

3. 機体状態の受信 — [mavlink_comm.py](./mavlink_comm.py) の受信スレッド（1 本、`mavlink-rx`）が `HEARTBEAT` / `GLOBAL_POSITION_INT` / `ATTITUDE` を受信し、1 パスでバッファを drain して最新値キャッシュへ更新します（12794 の drain 受信を通信部へ移設）。`monitor_vehicle(comm)` は 5ms 周期で `comm.snapshot()` を読み、seq の変化だけを処理します。Guided モード・アーム状態・姿勢（鮮度判定用の受信時刻も記録）・現在位置を反映します。

4. 離陸指令 — Guided かつアーム済みを検出すると、約 3 秒後に `send_takeoff_command(comm, TAKEOFF_ALT)` を呼びます。通信部の `takeoff()` が `MAV_CMD_NAV_TAKEOFF` を送ります。目標高度（home 相対）に達した後、追跡目標の送信を許可します。

5. ARから目標位置を計算 — マーカーから位置・姿勢を取得し、[local_frame.py](./local_frame.py) の変換関数で REF 原点基準のローカル NED を求めます。

6. Guided目標を送信 — Guided 中かつ離陸後であれば、カメラ追従とキーボード操作の両方から `send_local_target(comm, x, y, z, home_down_m)` を呼びます。`send_local_target()` が水平を REF 基準の緯度経度へ、高度を home 相対高度へ変換し、`send_setpoint(comm, lat_i, lon_i, alt, yaw_deg=TARGET_YAW_SEND_DEG)` を経由して、通信部の `setpoint()` が `SET_POSITION_TARGET_GLOBAL_INT` を送ります。マスクは `MASK`（既定 `0x09F8`、環境変数 `AR_HOOK_MASK` で変更可）、yaw は `TARGET_YAW_DEG`（既定 `0`＝北向き、環境変数 `AR_HOOK_TARGET_YAW_DEG` で変更可、実送信値は `TARGET_YAW_SEND_DEG`）です。

7. 終了処理 — `main()` の `finally` が `comm.stop()` を呼び、受信スレッドの停止と接続のクローズを行ってから CSV を保存します。

## MAVLink送信のスレッド排他（通信部の送信ロック）*

1. 背景 — 同一MAVLink接続に対して、カメラスレッド（最大40Hzの`camera_tracker_loop`）とキーボードスレッド（20Hzの`control_loop`）が同時に送信します。`pymavlink`の書き込みはスレッドセーフではないため、送信フレームの競合リスクがあります。`io_lock`は共有状態の保護専用です。

2. 送信ロック — 95501 の `mav_send_lock` は、19d3881 の通信部移行に伴い [mavlink_comm.py](./mavlink_comm.py) の `MavlinkComm._send_lock` へ移設しました。`AR-hook1.py` には送信ロックを置かず、`m.mav.*_send` も直接呼びません（送信ロックが二重にならない構成）。

3. ロックの閉じ込め — ロックは通信部の `_send()` 内だけで取得するため、呼び出し側で`with`を書く必要はありません。保持区間は送信処理のみで、sleep・受信・print・ファイルI/Oは入れていません。`send_setpoint()`はyawを`math.radians()`で事前計算してから通信部へ渡します（9c2a5 の yaw 引数は通信部経由でも維持）。

4. 取得順序 — `io_lock` → 通信部の`_send_lock`の一方向のみとし、逆順は禁止です。`io_lock`を保持したまま送信ラッパーを呼ばず、送信ロックを保持したまま`io_lock`を取得しません。現在の送信呼び出しは`io_lock`非保持区間だけです。

5. 受信の前提 — 受信（`recv_match`）は通信部の受信スレッド1本だけが行い、送信ロックを取得しません。そのため送信ロック内で受信待ちに入りません。

6. 検証 — [test_mavlink_comm.py](./test_mavlink_comm.py)で送信直列化とロック順序（AST検査）を確認します。[test_mav_send_lock.py](./test_mav_send_lock.py)は、ロックを迂回した送信で混線を検出できること（検出力）と、`AR-hook1.py` に未保護の送信呼び出しが無いことを確認します。
## 2026-11-18 変更点（AR-hook1 ローカルNED原点と高度基準の統一）

### 1. ローカルNED原点を1箇所に統一（方針(a)を採用）
- 原点の定義を [local_frame.py](./local_frame.py) の `REF_LAT/REF_LON/REF_ALT` だけにしました。AR-hook1.py 側の再定義は削除し、importして使います。
- 起動後最初の `GLOBAL_POSITION_INT` で `gps_origin` を決めて `gps_now` を起動時原点へ正規化する処理を廃止しました。
  - 選定理由: Motive側（send_GPS3.pyやzigzag）は固定REF基準でGPSを生成しており、受信側だけ起動時原点にすると離陸地点とREFの差が追従目標に一定バイアスとして乗るためです。固定REFなら異なるCSV間でも原点を共有でき、変換関数は不変の定数だけを参照する純粋関数になってオフライン検証できます。
- `gps_origin` は「離陸地点（EKF home）をREFフレームで表した参照点」に意味を変更しました（位置の減算・正規化には使いません）。`z` は離陸地点のDown[m]で、初期値は未確定を表す `nan` です。
- `gps_now` はREF原点基準のローカルNED（正規化なし）になりました。CSVの `GPS_Drone_X_m/Y_m/Z_m` はカラム名・並びを変えず、値の意味だけが「REF基準」に変わります。

### 2. 高度基準の統一
- 送信高度の定義を「EKF home（離陸地点）相対高度」に統一しました（`MAV_FRAME_GLOBAL_RELATIVE_ALT_INT` の要求に合わせるため）。
- 変換は `local_down_to_home_relative_alt()` の1関数だけを通し、送信は必ず [send_local_target()](./AR-hook1.py#L981-L1003) 経由にしました。定義は関数のdocstringに明記しています。
- `gps_to_local_xyz()` へは `GLOBAL_POSITION_INT.alt`（AMSL）を渡すように変更しました。旧実装は `relative_alt` を渡しており、起動が離陸後だとREF基準のzがずれていました。
- `TAKEOFF_ALT` / `TARGET_HEIGHT_ABOVE_TAKEOFF` は「離陸地点からの高さ」と定義し、`target['z']`（REF基準のDown）へは `alt_above_home_to_local_down()` で変換します。
- 離陸到達判定は `relative_alt >= TAKEOFF_ALT * 0.9`（home相対高度）に変更しました（旧実装は起動時原点で正規化したzとの比較）。
- キーボード `z`（降下）の下限判定は「離陸地点からの高さ0.05m」で行うように変更しました（旧実装はREF基準のDownを直接比較）。
- `t` キーはN/EをREF基準で設定し、高さは `TARGET_HEIGHT_ABOVE_TAKEOFF`（離陸地点から）に設定します。

### 3. io_lock の保護範囲
- `monitor_vehicle()` の `gps_origin` / `gps_now` / `target['z']` の読み書きをすべて `io_lock` 内に移しました（旧実装は `gps_origin` の読み取りがロック外でした）。
- カメラ追跡ループとキーボード操作ループは、送信直前に `target` と `gps_origin['z']` をロック内でスナップショットしてから送信します（`target['z']` をロック外で読んでいた競合を解消）。
- 原点 `REF_*` は不変の定数なのでロック不要です（実行時に書き換えません）。

### 4. 検証
- [test_local_frame.py](./test_local_frame.py) を追加しました。実機・Motive不要、標準ライブラリのみで実行できます。
  - 検証内容: REFと離陸地点が一致するときのGPS→ローカル→GPS往復誤差が0.01m未満、離陸地点がREFから北東5m・高度3mずれたとき追従目標にバイアスが出ないこと、送信altがhome相対高度であること。

### 5. 注意
